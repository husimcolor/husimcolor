# 각자 휴대폰 관계 검사 — Manus 자체 수행 범위 최종 E2E 보고서

작성일: 2026-09-30
상태: **Production 미배포 · 테스트 주문/테스트 세션만 사용**

## 결론

Manus Sandbox에서 가능한 범위의 최종 E2E를 완료했습니다.

- **서버·DB·두 브라우저 컨텍스트·PDF·실제 Resend 이메일** 흐름에서 오류 없이 완료했습니다.
- E2E 중 재접속 후 참여 동의 체크가 화면에 복원되지 않아 카드 저장과 제출이 막히는 문제를 발견했고, **서버에 저장된 동의 상태를 초대 컨텍스트로 반환하여 화면에 복원**하도록 최소 수정했습니다.
- 수정 후 A/B를 서로 다른 모바일 브라우저 컨텍스트에서 다시 실행해 저장·재접속·제출·결과 대기까지 확인했고, 실제 Resend 이메일도 `delivered`까지 확인했습니다.
- **Production 배포, 유료 공개 gate 변경, 기존 분석/PDF/Kakao 공유 변경은 하지 않았습니다.**

## 실제로 수행한 E2E 흐름

### 1. 분리 브라우저 A/B 사용자 흐름

| 단계 | 결과 |
|---|---|
| 테스트 결제 승인 → entitlement → 초대 관계 세션 생성 | 통과 |
| 서로 다른 두 무상태 모바일 브라우저 컨텍스트에서 A/B 토큰 열기 | 통과 |
| A/B 토큰이 같은 관계 세션의 서로 다른 참가자 슬롯에만 연결되는지 | 통과 |
| B가 A 제출 전에는 역할 정보를 보지 않는지 | 통과 |
| A가 남편·무교·3컬러를 저장 후 같은 링크를 새로고침 | 통과 |
| 저장된 역할·컬러·동의 상태가 재접속 화면에 복원되는지 | 통과 |
| A가 심리카드 3장을 선택해 최종 제출 후 대기 화면으로 전이 | 통과 |
| B가 초대 링크에서 `상대방이 ‘남편’으로 참여하고 있습니다.` 안내를 받고 아내 역할로 제출 | 통과 |
| B 제출 뒤 PDF 생성 및 이메일 처리 대기 화면으로 전이 | 통과 |

### 2. 결과/PDF/이메일/권한 흐름

| 검증 항목 | 결과 |
|---|---|
| 양측 제출 전 결과·PDF outbox가 생성되지 않는지 | 통과 |
| 양측 제출 후 private PDF와 outbox가 정확히 한 건 생성되는지 | 통과 |
| `result@husimcolor.com` → `support@husimcolor.com` 실제 테스트 이메일 발송 | 통과 |
| outbox `sent`, 발송 시도 `1회`, provider message ID·발송 시각 기록 | 통과 |
| Resend 개별 발송 상태 `delivered` | 통과 |
| 같은 outbox의 재발송 시도 차단 | 통과 (`not_claimed`) |
| 이메일 성공 후 관계 세션 `completed` 전이 | 통과 |
| 완료된 초대 링크의 답변 수정·재제출 차단 | 통과 (`RELATIONSHIP_INVITE_COMPLETED`) |
| 별도 결과 토큰으로만 완료 결과·실제 역할 조회 | 통과 |
| 완료된 A/B 초대 링크 UI가 `이미 완료된 검사입니다.` 화면으로 전이 | 통과 |
| 별도 결과 토큰 UI가 `커플 세션 결과`를 표시 | 통과 |

> Resend의 `delivered`는 수신 메일 서버가 최초 수락한 상태입니다. Sandbox에는 `support@husimcolor.com` 사서함 UI 로그인 권한이 없으므로, 수신함/스팸함 표시와 PDF 첨부파일의 실제 열람은 사용자 확인 항목으로 남습니다.

## 동시·중복 제출 및 역할 검증

서버 E2E에서 다음을 추가 확인했습니다.

- 동시·중복 제출은 compare-and-set 상태 전이로 한 요청만 리포트 생성 권한을 선점합니다.
- 중복 제출은 `RELATIONSHIP_INVITE_LOCKED`로 차단합니다.
- 남편 뒤 여자친구처럼 맞지 않는 역할 조합은 서버에서 차단합니다.
- 부모·자녀는 딸이 먼저 제출해도 엄마-딸처럼 **실제 역할 기준**으로 관계 유형이 확정됩니다.
- 역할·성별·동의·컬러·카드 초안은 revision 기반으로 저장됩니다.

## 발견·수정한 사항

### 재접속 시 동의 상태 복원

**발견:** 참가자가 기본 정보·동의·컬러를 저장한 뒤 링크를 새로고침하면 서버에는 `consentAccepted=true`이지만 화면 로컬 상태가 `false`로 초기화되었습니다. 이 상태에서는 심리카드 3장 저장 및 최종 제출이 진행되지 않았습니다.

**수정:**

1. 관계 초대 컨텍스트에 저장된 `consentAccepted` 값을 포함했습니다.
2. 초대 검사 화면이 컨텍스트를 불러올 때 저장된 동의 값을 복원하도록 했습니다.
3. TypeScript 및 관계 초대 회귀 테스트를 통과한 뒤, 분리 브라우저 A/B E2E를 처음부터 재실행했습니다.

기존 한 휴대폰 검사·개인 심화·결과 문구·분석 로직·PDF 구조·Kakao 공유에는 변경을 가하지 않았습니다.

## 테스트 데이터 정리

- 중간 자동화 재시도로 생성됐으나 제출이 완료되지 않은 브라우저 테스트 세션 6건은 `failed / BROWSER_E2E_ABORTED_TEST_DATA`로 종료했습니다.
- 성공한 E2E 세션은 실제 PDF 발송·완료 링크 잠금·결과 토큰 분리를 재현할 수 있는 테스트 감사 레코드로만 남겼습니다.
- 테스트 수신 주소는 `support@husimcolor.com`만 사용했습니다.
- 실제 고객 주문·고객 이메일·운영 Production 데이터는 사용하거나 수정하지 않았습니다.

## 사용자가 실물 휴대폰에서 확인할 항목

1. **실물 iPhone Safari**: 초대 링크 열기 → 기본 정보/동의/컬러 일부 저장 → 브라우저 종료 또는 네트워크 이탈 → 동일 링크 재접속 → 동의·저장값 복원
2. **실물 Android Chrome 및 Samsung Internet**: 카카오톡 또는 문자로 보낸 링크 열기 → A/B 각자 검사 → 결과 복귀
3. **카카오·네이버 인앱브라우저**: 링크 열기, 공유 시트, 스크롤, 앱 전환 후 복귀
4. **Toss 공식 테스트 결제창**: 실제 테스트 카드/앱카드 인증과 성공·취소·복귀 흐름
5. **`support@husimcolor.com` 메일함**: 수신함·스팸함에서 테스트 메일, PDF 첨부파일 이름·다운로드·한글 렌더링 확인
