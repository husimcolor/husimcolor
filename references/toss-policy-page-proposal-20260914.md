# Toss 심사 대비 정책 페이지·연결 상태 및 수정 제안

> **법률 검토 전 작업안입니다.** 아래 제안은 현재 서비스·코드·공개 화면과 공식 안내를 바탕으로 한 운영 설계이며, 최종 이용약관·개인정보처리방침·환불 고지 문구는 전자상거래 및 개인정보보호 전문 검토 후 확정해야 합니다.

## 1. 점검 결론

사업자정보는 2026-09-14 Production에 반영되어 공개 첫 화면, 관계 상품 선택, 무료 컬러 선택의 상세 연결에서 확인할 수 있다. 다만 프로젝트 코드와 공개 라우팅에는 **이용약관, 개인정보처리방침, 환불·취소정책을 독립 페이지로 제공하거나 서로 연결하는 구현이 현재 없다.** 따라서 Toss 실결제 심사 전에는 정책 페이지를 새로 만들고, 공개 푸터·상품 상세·결제 직전 동의·결제 완료 안내에서 동일한 버전의 정책으로 연결해야 한다.

현재 일반 고객 대상 유료 분석은 공개 차단 상태다. Production 서버 응답에서 `paidAnalysisPublicEnabled=false`를 확인했으며, 이번 정책 점검은 실결제를 활성화하지 않는다.

| 점검 항목 | 현재 상태 | 심사 전 권고 |
|---|---|---|
| 사업자정보 | 공개 화면 및 `/business-info`에 표시됨 | 통신판매업 신고번호 보유 시 추가 표기 |
| 이용약관 | 독립 페이지·링크 없음 | 공개 정책 페이지와 결제 전 동의 추가 |
| 개인정보처리방침 | 독립 페이지·링크 없음 | 실제 수집·위탁·보유 구조에 맞춘 전문 작성 |
| 환불·취소정책 | 독립 페이지·링크 없음 | 디지털 분석·코칭 예약을 분리한 전문 작성 |
| 상품·가격 표시 | 분석 상품 가격과 준비중 상태 표시 | 정식 판매 시 실제 결제금액·제공시점·취소 규칙을 상품별 고지 |
| 실결제 | 일반 고객 비활성 | Toss 심사·실결제·웹훅·모바일 QA 완료 뒤 별도 승인으로 활성화 |

토스페이먼츠는 비실물 상품에 대해 제공기간과 환불정책, 실제 판매되는 상품과 결제금액의 일치, 비회원 구매 가능 여부 및 실제 운영 사이트·앱의 결제 연동 완료를 심사 전 확인하도록 안내한다. 또한 홈페이지 하단에 상호, 대표자, 사업자등록번호, 주소, 유선번호와 해당 시 통신판매업 신고번호를 표시하도록 안내한다.[1]

## 2. 권장 정책 페이지 구조

### 2.1 공개 푸터와 공통 연결

현재 사업자정보 푸터 아래에 다음 네 개의 텍스트 링크를 같은 우선순위로 배치하는 구성을 권장한다.

| 링크 | 권장 경로 | 역할 |
|---|---|---|
| 이용약관 | `/terms` | 서비스 계약, 상품, 결제, 이용자 의무 및 책임 한계 |
| 개인정보처리방침 | `/privacy` | 수집·이용·보관·위탁·권리행사 고지 |
| 환불·취소정책 | `/refund-policy` | 디지털 분석과 코칭 예약의 취소·환급 기준 |
| 사업자정보 | `/business-info` | 현재 구현 완료된 사업자 식별·고객문의 정보 |

링크는 공개 첫 화면, 관계 상품 선택, 향후 코칭 판매 페이지, 주문서·결제 직전, 결제 완료 페이지에 모두 노출한다. 분석 결과·PDF·Kakao 공유 화면에는 내용을 덧붙이지 않고, 필요한 경우 기존 하단 공통 푸터를 통해서만 연결한다.

### 2.2 이용약관 초안에 포함할 구조

이용약관은 휴심컬러가 제공하는 무료 컬러 체험, 유료 개인·관계 분석, 향후 코칭 예약을 구분해 정의해야 한다. 각 상품의 제공 방식, 가격, 결제 승인 기준, 비회원 주문·계정 연결, 결과 접근·보관, 고객문의 방법, 약관 변경·고지 절차, 서비스 중단·오류 처리, 분쟁·준거 기준을 별도 조항으로 둔다.

특히 컬러·심리카드 기반 결과는 자기이해와 관계 성찰을 위한 정보이며 의료·정신건강 진단이나 치료를 대체하지 않는다는 성격과 한계를 **결과 문구가 아닌 약관·상품 안내**에서 분명히 고지하는 구성이 적절하다. 기존 분석 문구·로직·결과 구조는 수정 대상이 아니다.

### 2.3 개인정보처리방침 초안에 포함할 구조

개인정보처리방침은 문구를 먼저 만들기보다 실제 데이터 흐름을 확정한 뒤 작성해야 한다. 현재 코드·설계상 확인해야 할 항목은 회원 OAuth 식별 정보, 비회원 이메일, 주문·결제 상태, 쿠폰·구매권한, 검사 입력값, 결과·PDF, 고객문의, 후기, 접속·오류 기록이다. 목적·보유기간·파기 방식·위탁/제공 여부를 항목별 표로 분리해야 한다.

| 확인·확정이 필요한 사실 | 정책 반영 방향 |
|---|---|
| 회원·비회원 결과/PDF 보관 | 회원 1년, 비회원 7일이라는 기존 서비스 설계를 실제 파기 작업·주문 최소 보존 의무와 함께 구분 고지 |
| 검사 입력의 종교 등 민감 가능 정보 | 수집 필요성 최소화, 선택 항목 여부, 별도 동의·접근통제 필요성을 개인정보 전문 검토로 확정 |
| 결제·이메일·파일·OAuth 서비스 | Toss Payments, Resend, OAuth 인증, 실제 호스팅·파일 저장 사업자별 위탁 또는 제3자 제공 구분을 실제 계약·데이터 흐름에 따라 확정 |
| 개인정보 보호책임자 | 성명·연락처·처리방침 시행일을 사업자가 확정한 뒤 기재 |
| 권리 행사 | 열람·정정·삭제·처리정지·문의 접수 경로와 처리 절차를 `support@husimcolor.com` 기준으로 확정 |

개인정보 처리 목적과 보관기간, 수탁자·제공 여부는 운영 인프라와 실제 계약 조건이 바뀌면 함께 개정되어야 한다. 추정한 외부 사업자나 보관기간을 문서에 임의로 기재해서는 안 된다.

### 2.4 환불·취소정책 초안에 포함할 구조

환불 정책은 하나의 고정 규칙으로 합치지 말고 **디지털 분석**과 **코칭 예약**을 분리한다. 일반 전자상거래에서는 통상 7일 내 청약철회가 안내되지만, 용역·디지털콘텐츠 제공이 개시된 경우에는 예외가 가능하다. 다만 제한 사실을 소비자가 쉽게 알 수 있도록 명확히 표시하고, 디지털콘텐츠의 경우 시험 사용 또는 충분한 정보 제공 등 요건을 검토해야 한다.[2]

| 상품군 | 현재 설계와 맞춘 정책 초안 방향 | 구현 전 법률 검토·확정 필요사항 |
|---|---|---|
| 개인·부부/연인·부모/자녀 분석 | 결제 후 **첫 컬러 선택이 서버에 기록되기 전**에는 전액 환불 요청을 허용하고, 그 기록 시점을 서비스 제공 개시 후보로 사용 | 제공 개시 고지·동의 방식, 청약철회 제한의 적법한 적용, 오류·중복결제 예외 |
| 결과/PDF 제공 | 결과 생성·PDF 발송 실패는 고객 귀책 취소가 아니라 운영 장애로 분류하고 재생성·재발송 또는 환불 검토 흐름 제공 | 재시도 횟수·대체 제공·환불 승인 기준 |
| 1:1 프리미엄·부부/커플·기타 관계 코칭 | 예약 전날 23:59:59 KST까지 전액 취소라는 기존 운영안은 정책 후보로 유지 | 예약 확정 시점, 일정 변경, 당일 취소·노쇼, 천재지변·사업자 취소, 소비자분쟁해결기준 적용 여부 |
| 표시·계약과 다른 제공 | 상품 설명·계약과 다른 경우의 환급·고객 지원 경로를 별도 명시 | 환급 기한·증빙·분쟁 처리 책임 |

공공 법령 안내는 통신판매업자가 용역·디지털콘텐츠의 청약철회 시 대금을 3영업일 이내에 환급해야 한다고 설명하며, 카드 등 결제수단으로 지급된 경우 결제업자에 대해 청구 정지 또는 취소를 지체 없이 요청하도록 안내한다.[2] 이 내용은 운영 기능과 고객 고지의 기준으로 검토하되, 실제 적용 문구·기한·예외는 법률 검토 후 확정해야 한다.

## 3. Toss 심사 전 구현 우선순위 제안

| 단계 | 구현 범위 | 결제 공개 여부 |
|---|---|---|
| A. 사실 확정 | 통신판매업 신고번호, 개인정보 보호책임자, 실제 위탁처·파일 저장·호스팅, 코칭 예약 취소 기준, 정책 시행일 확정 | 계속 비활성 |
| B. 정책 페이지 | `/terms`, `/privacy`, `/refund-policy`과 공통 푸터 링크, 문서 버전·시행일·개정 이력 추가 | 계속 비활성 |
| C. 결제 고지 | 상품 상세의 가격·제공시점·환불 요약, 주문서의 약관/개인정보 동의 기록, 디지털 제공 개시 별도 확인 | 계속 비활성 |
| D. 운영·감사 | 정책 버전과 동의 시각을 주문에 기록, 환불 요청·승인·Toss 취소·알림 이력 연결 | 심사·QA 완료 뒤 별도 검토 |
| E. 실결제 전환 | Toss 라이브키·웹훅·취소 API·실기기 성공/취소/복귀·이메일 재시도 E2E 검증 | 별도 명시 승인 후에만 활성화 |

## 4. 즉시 확인이 필요한 정보

다음 값은 코드에 추정으로 넣지 말고 사업자 또는 법률 검토를 통해 확정해야 한다.

1. **통신판매업 신고번호**와 표기 여부
2. **개인정보 보호책임자**의 성명·연락처 및 권리 행사 처리 담당
3. 실제 운영 인프라별 **개인정보 위탁/제3자 제공** 구분과 보관 위치
4. 디지털 분석의 **서비스 제공 개시** 고지·별도 동의 문구
5. 코칭의 **예약 확정·변경·당일 취소·노쇼** 세부 기준
6. 분쟁·장애·중복결제 시 고객지원과 환급 승인 절차

## 5. 이번 단계에서 하지 않은 변경

정책 페이지·약관 문구·결제 동의 UI·환불 기능은 아직 만들지 않았다. Toss 실결제와 유료 공개 게이트도 비활성으로 유지한다. 기존 컬러심리 분석 문구·로직·결과·PDF·Kakao 공유 구조는 변경하지 않았다.
