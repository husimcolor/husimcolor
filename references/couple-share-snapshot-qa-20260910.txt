# 커플 고유 공유 링크·결과 스냅샷 QA

## 원인 확인

- 기존 카카오 공유 링크는 모두 `/couple-result`로만 생성됐고, 이 화면은 항상 브라우저의 `@couple_session`만 읽었다.
- 따라서 카카오톡이나 다른 브라우저에서 링크를 열면 공유 시점 결과가 아니라 해당 브라우저에 남아 있던 최근 로컬 검사 결과가 표시될 수 있었다.

## 로컬 독립 결과 1·2 검증

- **결과 1 (부부)**: A `레드·블루·라벤더`, B `그린·인디고·핑크`, 발급 shareId `7912b2bd-d0f2-402c-90bb-3bc75b5f69e5`.
- **결과 2 (연인)**: A `핑크·라벤더·그린`, B `블루·옐로우·브라운`, 발급 shareId `a3b06097-f423-4cbf-95d2-03d00bcd5893`.
- 결과 2를 로컬 세션에 저장한 뒤 결과 1의 링크를 열었을 때, 화면은 남아 있던 연인 결과가 아니라 부부·A `레드·블루·라벤더`·B `그린·인디고·핑크` 스냅샷을 표시했다.
- 결과 1 스냅샷 저장 크기는 14,893 문자 / 30,286 bytes로 현재 저장 컬럼 범위 안이었다.

## 로컬 독립 결과 3

- **결과 3 (부부)**: A `블랙·화이트·옐로우`, B `오렌지·코랄·틸`, 발급 shareId `6c4b58e0-5983-41cf-9147-b4278b6be1c3`.
- 결과 1·2·3은 서로 다른 UUID를 사용하며, 각 결과의 관계 유형·두 사람의 컬러·심리카드 및 관계 분석 스냅샷을 별도의 데이터 행으로 저장한다.

## 공유 링크 교차 세션 검증

- 결과 3의 부부 로컬 세션이 남아 있는 상태에서 결과 2 링크를 열었을 때, 화면은 정확히 **연인**, A `핑크·라벤더·그린`, B `블루·옐로우·브라운` 및 해당 관계 역할·관계 분석으로 복원됐다.
- 결과 2 링크에서 이전 아빠-딸 결과나 현재 브라우저에 있던 결과 3이 표시되지 않았으며, URL의 `shareId` 스냅샷이 우선 적용됐다.

## 로컬 세션 없는 조건

- 브라우저의 `@couple_session`을 삭제한 뒤 결과 1 링크를 다시 열었다. 저장소 값은 `null`이었으나 화면은 **부부**, A `레드·블루·라벤더`, B `그린·인디고·핑크` 및 해당 관계 분석을 정상 표시했다.
- 이 결과는 다른 휴대폰·시크릿 브라우저처럼 로컬 검사 데이터가 없는 환경에서도 `shareId`만으로 공유 시점의 결과를 조회하는 경로가 작동함을 확인한다.

## 카카오 공유 링크 준비 경로

- 현재 로컬 브라우저에는 Web Share API가 없고 클립보드 쓰기 API만 있어, `카카오 공유` 버튼은 같은 고유 `shareId` URL을 클립보드에 준비하는 대체 경로를 사용한다.
- 실제 Android·iOS 환경에서는 동일한 URL을 시스템 공유 시트로 전달해 카카오톡을 포함한 설치된 공유 앱에서 보낼 수 있도록 구현되어 있다. 이 검증 환경에서는 개인 카카오톡 계정으로 실제 전송을 완료할 수 없으므로, 전송 전 링크 생성·독립 조회·로컬 세션 없는 조회까지를 확인했다.

## 적용 범위 및 최종 로컬 회귀

- 고유 `shareId`의 생성·저장·조회는 **부부·연인** 결과에만 적용했다. 부모·자녀·친구·동료·형제자매의 경량 결과는 기존 이미지·링크 공유 흐름을 그대로 유지한다.
- 부부·연인 공유 스냅샷 API는 `연인`과 `부부` 관계 유형만 저장·조회하도록 서버 입력 검증도 제한했다.
- 전체 회귀 결과는 13개 테스트 파일 통과, 91개 통과·1개 스킵이며 TypeScript와 공백 검사도 통과했다.
