# 현재 세션 기준 카카오 공유 QA

## 검증 목적

카카오 공유를 누른 시점의 관계 세션이 새 불변 `shareId` 스냅샷으로 저장되고, 이후 다른 검사를 진행해도 기존 링크의 결과가 바뀌지 않는지 확인했다.

## Production API·링크 검증

| 순서 | 공유 세션 | 생성 shareId | Production 복원 결과 |
|---|---|---|---|
| A | 부부 · A: 핑크/그린/라벤더, B: 블루/옐로우/브라운 | `f222b49f-8cad-44a8-a38e-54fb4682d285` | `부부`, 해당 A/B 컬러·심리카드와 현실협력형 결과가 복원됨 |
| B | 엄마-딸 · 엄마: 그린/세이지/라벤더, 딸: 옐로우/핑크/코랄 | `18dcec20-592c-4134-9e70-6bac928e1088` | `엄마-딸`, 실제 호칭·A/B 컬러·심리카드·부모자녀 전용 결과가 복원됨 |

두 스냅샷은 서로 다른 UUID로 생성됐으며, Production API에서 각각 다시 조회했을 때 관계 유형·컬러·심리카드가 교차하거나 덮어써지지 않았다. 실제 운영 링크도 각각 부부 결과와 엄마-딸 결과를 별도로 렌더링했다.

## 구현 확인

- 공유 버튼은 결과 도달 시 자동 저장된 ID나 현재 URL을 재사용하지 않고, 클릭 시점의 `sessionData`로 새 스냅샷을 생성한다.
- 이전 `AsyncStorage` 세션에 남은 `shareId`는 새 스냅샷에서 제외한다.
- 연인·부부뿐 아니라 부모·자녀·친구·형제자매·동료도 동일한 `shareId` 저장·조회 계약을 사용한다.
- DB는 기존 스냅샷을 갱신하지 않고 새 UUID 행을 추가하므로, A 링크는 B 검사 이후에도 바뀌지 않는다.
