# Production Toss 테스트 공개 흐름 검증 기록

> **검증일:** 2026-10-04 KST
> **범위:** `husimcolor.vercel.app`의 유료 심화분석 공개 **Toss 테스트키 운영**
> **제외:** Toss 라이브키·실제 청구·운영 결제 전환

## 배포 및 설정

- Production 공개 테스트 gate와 Toss 테스트 runtime을 활성화했다.
- 라이브 결제 키나 실제 청구 설정은 변경하지 않았다.
- 운영 DB에는 테스트 주문을 매출 제외(`isTest=true`)로 기록한다.
- Production에 고객 지정 개별 쿠폰을 위한 `assignedCustomerId`의 additive migration과 관리자 발급 기능을 반영했다.
- 공개 오픈기념 할인은 KST 2026-10-30 23:59:59까지, 개인·부부/연인·부모/자녀 심화분석에만 적용되며, 오프라인 코칭에는 적용되지 않는다.
- 최종 Production 배포 workflow: GitHub Actions run `37206717317` 성공.

## Production에서 확인한 항목

| 항목 | 결과 |
|---|---|
| 공개 테스트 runtime | 활성화. 화면에 실제 청구 없음·테스트 주문 매출 제외 안내 표시 |
| 오픈기념 할인 견적 | 개인 29,000원 → 23,200원, 부부·연인 59,000원 → 47,200원, 부모·자녀 39,000원 → 31,200원 |
| Toss sandbox 진입 | 부부·연인 47,200원으로 실제 Toss sandbox 결제창 진입 확인 |
| 테스트 주문·이용권 | Production 테스트 원장에서 paid/approved, 이용권 consumed 확인 |
| A/B 관계 흐름 | A·B 기본정보 저장 후 제출, 두 링크에서 같은 통합해석 확인 |
| 재진입 방지 | A·B 완료 링크 재접속 시 검사 시작 화면 대신 결과 화면으로 연결 |
| PDF | A와 B 모두 결과 화면에서 PDF 접근을 확인. Chrome에서 실제 PDF 다운로드 정상 확인; 카카오톡 내부 브라우저의 다운로드 실패는 별도 호환성 보정 배포 대상으로 기록 |
| 이메일 | 결제자용 PDF outbox 1건이 sent, 시도 1회, 오류 없음으로 확인 |
| 중복 방지 | 해당 테스트 주문당 PDF 이메일 outbox 1건만 존재함을 확인 |

## 검증 방식 구분

- **실제 Toss sandbox 승인 및 전체 흐름:** 사용자 휴대폰에서 할인 적용 후 Toss sandbox 성공 callback, 주문·이용권, A/B 제출, 양쪽 결과 접근, A PDF 다운로드와 결제자 이메일 수신까지 확인했다. 실제 청구는 발생하지 않았다.
- **남은 보정:** B의 결과 링크를 Chrome에서 열면 PDF 다운로드가 정상이나, 카카오톡 내부 브라우저에서만 다운로드가 실패했다. 이 링크의 권한·결과·PDF를 유지한 채 카카오 권장 GET 다운로드 헤더와 외부 Chrome 전환을 추가 배포한다.

## 운영 제약

- 이는 **테스트 운영**이며 실제 결제는 발생하지 않는다.
- 라이브키 전환, 실제 청구, 정식 유료 결제 오픈은 별도 승인과 전환 계획이 필요하다.
- 카카오 회원 로그인 UI의 동일 흐름은 이 기록의 범위에 포함하지 않는다.
