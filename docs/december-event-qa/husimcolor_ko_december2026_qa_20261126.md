## 3. 아직 확인하지 않은 항목과 배포 보류 이유

실제 분리 DB에서 할인 주문부터 리포트 생성·저장·재조회·PDF까지의 연결 검증은 준비만 완료했고 실행하지 않았습니다. 전용 로컬 DB에 신규 테이블만 생성하는 방식의 승인이 대기 중입니다. 강제 스키마 동기화는 실행하지 않습니다. 테스트 행을 운영 DB에 생성하지 않습니다.

개인 결과의 준비된 검증 경로는 기존 생성 payload의 로컬 저장·재조회이며, 관계 결과는 기존 서버 저장·조회 API입니다. 개인 결과용 서버 snapshot API가 확인된 것처럼 표현하지 않습니다.

운영 DB 연결의 과거 복구 기록과 민감 변수 갱신 메타데이터는 확보했습니다. 그러나 현재 Vercel Production 연결과 실행 환경 연결의 직접 동일성 대조는 마무리되지 않았습니다. 읽기 전용 접속 성공이나 세 상품 가격 일치만으로 같은 운영 DB라고 단정하지 않았으며, 운영 mutation을 보류했습니다.

Android 실기기, 네이버·카카오 인앱, 실제 카카오 로그인, 실제 Toss SDK·승인, 실제 이메일 발송은 이번 검사에서 확인하지 않았습니다. 실제 결제·고객 이메일은 실행하지 않았습니다. 브라우저 SDK stub 기록은 청구·승인 성공 증거가 아닙니다.

## 4. 소스·백업·복구

저장소는 `husimcolor/husimcolor`, 검토 브랜치는 `feature/december-report-coupons`입니다. 기준 main은 `98f239d73f9e92a80a42e5123f1c12ae02448a7a`, 작업 시작점은 별도 전화·현장 코칭 변경을 포함한 후손 `c1f2846`입니다. 오래된 Manus 복원본은 이번 운영 소스로 사용하지 않았습니다.

[GitHub 검토 브랜치](https://github.com/husimcolor/husimcolor/tree/feature/december-report-coupons)에 소스와 검수 자료를 보관합니다. 다운로드 ZIP의 `BACKUP_MANIFEST.json`에 최종 소스 커밋, 브랜치, 작업 트리 상태, 운영 미배포·운영 DB 미변경 상태, 파일별 해시를 기록합니다.

추가 DB 대상은 행사 쿠폰 발급 원장 테이블과 상품 전용 쿠폰 3개·상품 규칙입니다. 기존 상품 정가, 회원, 주문, 결제, 고객 결과, PDF, 이메일을 수정하거나 재생성·재발송하지 않습니다. 운영 apply는 동일성·백업·승인이 확보된 경우에만 실행하도록 보호합니다. 기존 쿠폰 설정 충돌은 덮어쓰지 않고 중단합니다.

문제 발생 시 이전 운영 소스로 복구하고 행사 쿠폰의 신규 사용만 중지하는 방식을 우선합니다. 사용·예약 원장과 주문·결제·리포트는 보존합니다. DDL은 자동 커밋되므로 단순 DML rollback이 테이블 생성까지 되돌린다고 설명하지 않습니다.

ZIP에는 환경 파일, 비밀번호·API 키, `.vercel` 민감 파일, DB 덤프, 고객 개인 리포트·메일, 의존성, 빌드 산출물을 제외합니다. 캡처와 공개 샘플은 가상 데이터입니다. 실제 환경 비밀값 매칭과 원격 접속 문자열·GitHub 토큰 검사를 통과한 자료만 묶습니다.
